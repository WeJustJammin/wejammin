### MAJOR

**M1 (web8a, locale) — an unknown outcome whose read shows only the entry version moved forces adoption and a NEW request, not the byte-identical retry.**
- `apps/web/src/components/cms-locale/use-locale-save-reconcile.ts:44-57`: for `afterWrite === 'unknown'`, `sourceSame && snapshot.version !== expected.version` skips the `confirmed` branch, calls `hold()` (line 56) and returns `moved`. `use-locale-variant-form.ts:150-154` then blocks every save while `review.required`; the only way out is "Use the current source" (`adopt`, `use-locale-variant-form.ts:239-250`), which sets the new version, clears the status (line 249) and so erases "Save not confirmed".
- Probe `probe-v19-locale.test.tsx`: unknown outcome, read answers version 5 with the same source and hash → commit disabled, "Use the current source" shown; after adopting, no result heading remains; the second POST has a NEW idempotency key and `expectedVersion` 4 → 5. A version bump with an unchanged source is the likeliest sign that the first write committed; the form then sends a second write and never reports the first.
- Rule: the brief ("unknown outcome reconciled by a read BEFORE any retry is offered and the retry byte-identical"), DEC-244(3) ("an unknown-outcome retry is the identical request under its key and If-Match and never adopts the version the reconciling read saw") and BE03c 150 / BE00 (a retry is the identical request under its key; the replay is how the server reveals the truth). Related content and composition do this correctly (they say "may have been applied" and offer the identical retry).
- Fix: for an unknown outcome, a read with the same source and any other version must lift `unverified` WITHOUT `hold()` and WITHOUT touching `source`, keep the status, say the entry moved ("the translation may have been saved; sending again retries the same request and cannot save twice"), and leave the retry identical. Keep the review gate for a moved SOURCE if root wants it. A sharper verdict is available: the protected locale variant read (`cmsLocaleVariantRead`, DEC-205, browser route `apps/web/src/pages/api/v1/cms/entries/[entryId]/locales/[locale].ts`) shows whether the stored translation equals the request (recorded / not recorded), as the related-content form does with the rule read. Add a RED test for the version-only case (no test covers it today; `CmsLocaleVariantForm.refetch.test.tsx:108-114` moves the hash).
