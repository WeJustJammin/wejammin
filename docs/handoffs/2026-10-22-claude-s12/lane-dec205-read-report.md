## Scope
Operation `cmsLocaleVariantRead` (`GET /api/v1/cms/entries/{entryId}/locales/{locale}` -> `LocaleVariantRead { locale, activeFallbackChain, variant: LocaleVariantResource | null, fields: {fieldId, value}[], resolutions: LocaleFieldResolution[] }`), authorized as CMS-03C-04 (BE03c 93, 167, 193, 395, 1358-1370, 1390, 1424, 1620, changelog 1854).

## Decisions made in this lane (implementation-level, DEC-205 cites none of them)
- Resolutions come from `platform_private.cms_locale_resolutions` (the CMS-03C-20 core that `cms_resolve_locale_field` and the locale gate both call), one statement for every localizable (`localized`, `no_fallback`) active field, own revision = the locale's newest revision (the editorial-read form). The `none` field is not localizable and is not listed. The resolver is promoted (`20261014050500`), so only the lane `dec205` is staged.
- `fields` = the variant revision's stored values for those same fields (explicit JSON null listed as null; unwritten fields not listed; `[]` with no variant).
- Authority = `cms_require_entry_capability(actor, party, ['cms.author','cms.editor'], entry)`, the very helper CMS-03C-04 calls: it raises `FORBIDDEN`; the Worker adapter maps it to 403 `LOCALE_FORBIDDEN` with `details.reasonCode = capability_missing` (the one typed 403 of `CMS_SLICE_12_OPERATION_REASONS.cmsLocaleVariantRead`).
- Order: envelope 400 -> session 401 -> entry id / locale grammar 400 -> hidden/absent 404 -> edit authority 403 -> unsupported locale 404 (so a caller without edit never learns which locales exist) -> read.
- `supportedLocales` membership is the same exact (case-sensitive) `?` test the write uses; the DB accepts a lower-case entry id only, the Worker adapter lower-cases the contract id (as the DEC-195 adapter does).
- No ETag on the read: the form's `If-Match` is the entry version, served by the draft detail.
