## DEC-219 (cost bound and failure signal)
1. Failure signal. `cms_locale_observability_read_failed_total` (no labels) is registered and emitted on every failed, timed-out or malformed read (an invalid scheduled time included). The alert `locale_observability_unavailable` joins the composition policy (`CMS_COMPOSITION_ALERT_CODES`, snapshot member `localeObservabilityFailedReads`, threshold `4` strictly above = the fifth failure, window `600_000` ms, helper `countFailedLocaleReadsWithin`, inclusive at the exact window age). The probe keeps a bounded (64) in-process list of its own failure instants, evaluates the policy on each failed read and logs the alert event (allowlisted members only, no metrics member so the counter is not double counted). Limit, stated plainly: the database is the failing dependency so it cannot hold the count; a restarted or different isolate starts at zero, so the in-process alert is best effort and the durable backstop is a provider-side rule on the counter (none is deployed, as for every Slice 12 alert).
2. Cost. `staleLegalFields` is now `platform_private.cms_locale_stale_legal_field_count()`: a recursive CTE from the `active` entries, next distinct raw `locale` above the previous, then the newest row of each raw locale, then `distinct on (entry, lower(locale))` for the case-insensitive current row; same predicate and same answer (every existing gauge assertion unchanged and green). Per call the cost is live entries x locales (at most 32 per entry); superseded rows are not read.
3. DEVIATION to ratify. The brief and BE03c say "a skip scan of the existing `(entry_id, lower(locale), ...)` index". Under the FORCE ROW LEVEL SECURITY of `cms_locale_variants` that cannot work: the policy qual runs first and a user qualifier can be an index condition only if all its functions are leakproof; `lower()` is not (`pg_proc.proleakproof = false`, measured). EXPLAIN ANALYZE as `wejammin_cms_definer` showed the `lower(locale)` probes as filters, the whole entry read per probe, and the head probe choosing another index plus a Sort. The same applies to the dec205 reader's `lower()` predicates (not touched). I therefore added `INDEX(entry_id, locale, version DESC, created_at DESC, id DESC)` to `20261022100000` (keeping the spec'd `state` and `lower(locale)` indexes, which the window read and the current-row rule still name) and skip-scan the plain column, whose `=`/`>` on text and `=` on uuid are leakproof (plan B: index conditions, `actual rows=1` probes).
