### Proposed exact private helper contracts

All signatures are new, without defaults/overloads, CMS-owned, empty `search_path`, PL/pgSQL and `SECURITY INVOKER`; execute is private to the owner. No helper authenticates an arbitrary caller or treats a captured array as authorization/lock attestation.

- `platform_private.cms_entry_create_relation_fence(p_auth_user_id uuid, p_acting_party_id uuid, p_schema_version_id uuid, p_values jsonb) RETURNS uuid[]`, VOLATILE. Derives the complete request union from actual same-owner schema field/RelationDefinition rows, validates/prechecks it without target locks, locks each distinct external content target plus caller assignments in ascending target UUID order, then rechecks every occurrence. Returns the actual sorted unique target UUIDs, empty array when none. No storage writes or schema/default locks.
- `platform_private.cms_entry_create_relation_specs(p_auth_user_id uuid, p_acting_party_id uuid, p_schema_version_id uuid, p_field_definition_id uuid, p_value jsonb) RETURNS jsonb`, STABLE. Checks actual field/schema/owner membership and applies the existing create (`p_entry_id=NULL`) relation semantics without any row lock: shape, per-field cardinality/uniqueness, supported target kind, visibility, current expected-version equality and canonical `{targetId,targetKind,expectedTargetVersion,position,onUnavailable}` specs. This is not a public/general relation resolver replacement.
- `platform_private.cms_entry_create_default_lock(p_acting_party_id uuid, p_template_version_id uuid) RETURNS void`, VOLATILE. NULL is a no-op. For a non-NULL exact pin, prove the actual owner-scoped row exists before locking it `FOR SHARE`; acquire no slot, block, schema or authority lock. Missing/concealed is bare `NOT_FOUND`. Recheck the locked identity; do not accept an owner-less ID or replacement.
- `platform_private.cms_entry_create_default_require(p_auth_user_id uuid, p_acting_party_id uuid, p_content_type_id uuid, p_schema_version_id uuid, p_template_version_id uuid) RETURNS uuid`, VOLATILE because it calls the existing resolver. NULL returns SQL NULL. Otherwise call the exact existing compatibility resolver using server-derived Auth principal/acting context and actual type/version; return only the same supplied pin after success. No lock or storage write is introduced here.

`p_auth_user_id` means the result of `cms_actor`, NOT `author_person_id`: `cms_actor` delegates to `cfg_actor` (`20260902080000_content_schema_registry_authority.sql:2227–2235`), while `identity_actor_person` derives the separate assignment/author person. Resolver context's `authUserId` must use the Auth principal; no fabricated/manual verified-claim context, person-as-Auth substitution or new cache authority is allowed. `cms_acting_party` publishes existing scoped session state (`20261002192000_cms_session_scope_rls.sql:197–209`).

1. After completed replay and the existing strict request/type-version preflight, validate the complete immutable `values` envelope and relation inputs before target UUID casts or target locks. 2. Resolve every supplied relation field against this exact schema's immutable FieldDefinition/RelationDefinition. Validate each occurrence under its own definition, even when the same target appears in several fields. 3. Precheck ALL referenced external content targets with the current `cms_relation_target_visible` policy before taking ANY target lock. It does not reacquire person/tenure/grant authority after1. Keep every lock to commit.
5. After all waits, recheck each field occurrence's visibility, lifecycle/type/owner and expected target version with the lock-free specs helper. 6. After schema4, final field handling uses the new lock-free specs helper, not a first acquisition by the old per-field resolver. A lock-free create-specific path avoids both accidental late target locks and fresh assignment-row discovery. Keep the shared resolver and append/resolve/restore behavior unchanged.

## Default3, schema4 and exact compatibility

1. Capture `preflight_default_template_id` from the exact owner/type/version preflight row already selected by create, without taking schema4. Do not resolve a newer active schema or a binding as fallback. The relation fence above completes first.
2. With non-NULL default, call the owner-scoped default-lock helper at3. A foreign/missing row must fail before its lock. Do not lock `slots.allowedBlocks` registry rows: merely pinning a template reaches no compositions or blocks.
3. Replace the premature generic schema-lock call with an exact `SELECT ... FOR SHARE` of the requested owner/type/version row at4. Re-read the actual composite AFTER the wait; require the exact identity and active state. Activation winning retains create's existing `VALIDATION_FAILED` DETAIL `["/contentTypeVersionId"]`, not a switch to the new active version. Do not inherit the generic helper's `CONFLICT`-for-inactive behavior as create's setup mapping.
4. Require the rederived default to be `IS NOT DISTINCT FROM` the captured, already fenced default. A changed setup is refused at the existing schema-setup pointer; never acquire a replacement default at3 after holding4. Re-derive the complete relation union/field-definition identities from the same actual schema and unchanged values; no cached metadata may authorize a different closure after waiting.
5. Now resolve the exact pin through `cms_resolve_template_compatibility(jsonb)` against the exact actual type/version. Match its expected P0001 whole-message tokens only in a narrow block around that call: `NOT_FOUND`→bare `NOT_FOUND`; `INCOMPATIBLE`→`VALIDATION_FAILED` with exact pointer-array DETAIL; `WITHDRAWN`→`CONFLICT`; all other SQLSTATE/messages rethrow unchanged. Do not catch the whole create/E7 tail or reinterpret injected/programming faults as compatibility failures.
6. Existing resolver state semantics remain unchanged: reject retired/blocked, allow compatible superseded; do not add active-only filtering. Compatibility compares UUID identity, not spelling/case. No public `expectedTemplateVersionNo` operand is added.
7. Retain artifact/compiler/definition-hash, frozen protected-validator, locale, workflow-policy and activation-evidence checks against the fresh locked schema. Before any INSERT, all dependency decisions and final relation checks must be complete. The insert-time schema guard remains a backstop, not the primary fence.

Replace only the revision VALUES pin NULL with `initial_template_id`; taxonomy/parents, contentHash, author attribution, normalized values/relations, initial assignment's actually proven capability, event, resource mapping and E7 tail remain unchanged. Slots are not cloned/fabricated: downstream placement reads the exact stored template's existing literal slots. Preserve the QA's independent `main`/maxCount7 oracle rather than deriving an expected slot from the response.
