peer-build.mjs → peer-artifacts.mjs. The build helper independently derives
the same adjacent peer-credentials.c; it accepts no source override.
All imports are Node built-ins or these claimed sibling helpers.

The main module exports only buildPeerCredentialReader. Factory options have
exactly three own data-property keys. Linux, exact Node v22.23.1 and Node-API8
availability are checked before building. The factory creates no socket,
listener, proxy, tracer, service, daemon connection or reset.

Artifact helpers require canonical absolute paths, real regular files and
non-symlink objects. Each file is opened with O_NOFOLLOW; descriptor and named
identity are compared around complete-byte SHA256 reads. The compiler must be
executable and not set-ID. The run directory is current-UID-owned, mode0700 and
empty before an exclusive peer-credentials.node reservation. No caller
directory is removed.

Source/compiler/four sorted Node-API headers are checked before and after GCC.
The successful output must retain the exclusively reserved device/inode/UID
and contain bytes. Artifact checks bracket loading, and an opened output
descriptor pins the checked inode during the load. Every synchronous capability
read rechecks all bound file identities/hashes around native acquisition.
The deeply frozen metadata contains only the selected exact node/artifact
records, and the frozen capability contains only read, close, metadata.

The C addon uses only Node-API8 and Linux/POSIX interfaces. Its single private
export is readPeerCredentials(fd). It checks a numeric, finite, integral,
nonnegative descriptor within INT_MAX before the cast; fractions and
2**32 + fd cannot wrap. It requires a socket, SOCK_STREAM, AF_UNIX,
successful connected-peer lookup and exact-size SO_PEERCRED. It pins an owned
duplicate, compares descriptor fstat identities before/after, and closes only
that duplicate. It never consumes socket bytes or closes the caller's fd.
PID/UID/GID are kernel numbers; device/inode are lossless decimal strings.

## Compiler lifetime and cleanup

GCC is spawned explicitly without a shell in one detached Linux session/group,
with a fully constructed environment: fixed PATH/locale/timezone and the owned
run directory as TMPDIR. No ambient environment is spread or serialized.
There is no package installation, privilege or kernel-policy change.

The selected build timer is30seconds. A timeout attempts one SIGKILL only when
the unreaped child still matches its captured PID, parent, start ticks,
session/group and UID. No SIGTERM, escalation or unrelated process termination
exists. Child close and both drained streams precede the read-only admitted
session-absence check; the settlement phase is bounded as described below.

Failure evidence contains only closed error code/message plus bounded
exit/signal/boolean fields, stream byte counts and SHA256 values. No raw
stdout/stderr, ambient environment or request material is emitted/persisted.
On unproved settlement, a private Set retains the actual child/streams/state,
captured fence and owned run/output record. No reader is returned, suspect
artifacts remain, and no successful cleanup or integration authority is claimed.
Ordinary proved-drained failure may remove only the reserved owned output.

close() revokes synchronously before its first await, and shares one cleanup
operation across repeated calls. It does not depend on successful socket or
artifact validation to revoke. Cleanup checks the original run and output
device/inode/UID. Missing or foreign/replaced output is left untouched and
close may resolve; that does not claim the original artifact was removed.
Unrelated caller files and directories are retained. Native-library unloading
is neither attempted nor claimed.
