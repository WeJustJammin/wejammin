## Native finite construction and closure

C maps only its actual original child3/4 pipes through disjoint CLOEXEC scratch to
outer8/9, opens/maps the four actual named locks3–6 in order, and services CANCEL,
outer HUP and driver loss during every bounded nonblocking LOCKING retry. Each wait

LOCK_UN, lockfile replacement/chmod/chown, guessed row owner or new lock path.
Before its sole reserved fork it opens actual self pidfd7 and genuine-parent driver
pidfd10 with pre/post original-instance checks. Loss prevents another acquisition,
fork or ordinary ACK. Preserve exact12/13 versus inner8/9 topology and every alias.

I synchronously checks actual self-fdinfo3–10/full O_CLOEXEC before its fixed addon
compile and again across awaits. Native adoption separately checks actual F_GETFD's
FD_CLOEXEC bit1,
parent/current same-number locks, both pidfds and original C/O ancestry/live images.
No JS fd reader competes with the sole native8 reader. The reader's serialized
native latch consumes CANCEL/HUP before ADOPTION_ACK/release, before any TSFN call.
Only actual native ADOPTION_ACK plus post-live rechecks resolves adopted; a queued
notification, relayed status or callback return cannot authorize it.

The reader must keep servicing controls under partial-write/backpressure, with
fixed bounded buffers and burned write/ACK slots; no unbounded queue, dropped frame
or one-read-per-write assumption. TSFN is bounded notification to one wrapper-owned
fixed function only. Queue/notification failure cannot undo revocation or become
drain; retain uncertainty. Exact addon entry/method/notification ABI is still a
selection gate below, not permission to invent a callable native method set here.

owns allocation/cleanup; uncertain cleanup retains its actual state. After wrap
the finalizer owns allocation lifetime, while explicit cleanup may revoke/join/close
resources but cannot free behind it. Detach slots before one close, never retry EINTR.
