## First bounded implementation contract: Linux peer credentials

Build and verify the kernel-identity primitive independently before integrating a proxy or reset runner. This primitive proves socket peer facts only; it does not authorize a process, daemon operation, reset or acceptance receipt.

Use existing compiler/headers only, with sanitized compilation environment and no shell/package installer. The run directory must be fresh, owned by the current UID, non-symlink and mode0700. Refuse pre-existing output. Await compiler close and all streams, record actual source/compiler/header/output identities and hashes, and reject drift before loading or reading. Failure leaves no active capability. Normal/proved-drained failure closes owned compilation work; the explicitly bounded uncertain-drain exception below retains ownership/evidence and blocks integration.

Return a private frozen capability exposing `read(socket)`, `close()` and immutable build metadata. Foreign objects or matching serialized metadata do not create that capability. Closing revokes further reads. Clean only the exact generated artifacts owned by this build after work has drained; never remove caller directories or unrelated files.

`read(socket)` must obtain `{ pid, uid, gid, device, inode }` from the actual connected AF_UNIX stream descriptor. PID/UID/GID are kernel numbers; device/inode are lossless decimal strings. Validate the numeric descriptor and connected Unix stream, call `getsockopt(SO_PEERCRED)`, and compare descriptor `fstat` identity before/after. Never accept claimed credentials from request data. Reject invalid/closed/unconnected/non-Unix/non-stream descriptors and unsupported socket handles; no fallback to claimed values. A thin Node-API C addon restricted to Node-API version8 is proposed; no V8/libuv ABI dependency. Any use of the pinned Node socket handle must fail closed when unavailable, and must be exercised against actual Node22.23.1.

SO_PEERCRED describes peer credentials at connection establishment. It does not itself prove current PID lifetime, start ticks, ownership or request attribution. Integration must supply those additional fences; do not attach a later `/proc` observation and call it atomic proof.
