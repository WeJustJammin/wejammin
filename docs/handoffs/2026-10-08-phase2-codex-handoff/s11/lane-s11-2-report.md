## Design decisions (engineering, within the locked BE03b shapes)
- Guards are SECURITY INVOKER trigger functions with search_path '' (like cms_schema_review_guard); they name no DEFINER table grants. Where a guard reads another table (decision/assignment/schedule/lineage guards) lane 3's definer role needs SELECT on it; lane 3's functions name those tables anyway (the SEC-2 least-privilege sweep derives grants from function bodies, so I granted nothing to wejammin_cms_definer).
- Guard function names avoid the substrings pinned by the S10 scope test phase_02_slice_10_ev_eb_publication_scope.sql (entry_review|editorial_review|editorial_decision|publication|preview_token|schedule_publication).
- Refusal tokens follow the existing guard convention: IMMUTABLE_RECORD (frozen/append-only), CONFLICT (CAS/transition), VALIDATION_FAILED (bad creation image), DIRECT_CMS_TABLE_WRITE (write guard, fires first), plus the BE03b lowercase reason tokens where the guard mirrors a typed RPC refusal.
- Owner lineage and revision-belongs-to-entry are declarative composite foreign keys (id, owner_id) / (id, entry_id), not triggers.
