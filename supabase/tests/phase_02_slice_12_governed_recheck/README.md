The `pattern` kind of the recheck (a nested pattern review, the real `cms.pattern.activated.v1` event, the correlation id of the audit records) is
`../phase_02_slice_12_governed_recheck_pattern.sql`.

Labelled fixtures besides the S09 membership tenure: the lag fixture (`002-lapse-helpers`, the stored `approved` state that lags a grant that
ends by the calendar: 030, 040, 070 and the four other governed drivers), the tenure writes of 080, and two function-level faults in 070 (the
test-admin guards ONE private function and restores it byte for byte). No governed row is written by hand and no trigger is disabled.

To add a lag test: call `pg_temp.s12fr_lapse(organization, person, capability)` (the person still holds it, so nothing is invalidated; from then
on `cms_person_holds_capability` answers false for exactly that grant), make the assertions, and call `pg_temp.s12fr_restore()` before the next
section. Do not move the session clock instead: a zone 16 h or more from UTC breaks every timestamptz read back from text (SQLSTATE 22009) and a
smaller shift reaches the next day only at some hours of the UTC day.
