### Command-specific completion obligations

- ORG-01 records the selected creation mode, registry version and actor snapshot. Shadow/custodial and external-reference modes do not create an external identity, provider link or identifier.
- TYPE-01 refuses an unregistered/deactivated type before mutation. TYPE-02 ends exactly one active assignment and increments the organization version; it never deletes the organization or rewrites old assignments.
- MEM-01 refuses invitation when the organization lacks a capable actor or current governed terms. MEM-02 never changes current authority. MEM-03 requires the invited person’s self context and the current terms hash. MEM-04 performs immediate revocation even when the historical end date is disputed. MEM-05 does not change tenure authority.
- REP-01 validates both parties, scope and term before creating a pending edge. REP-02 writes only the current party’s confirmation. REP-03 writes revocation, invalidates projections and emits context invalidation in one transaction.
- MAN-01 derives grantor and source projection, then checks activity, domain, term, currency and ceiling as a subset. MAN-02 recursively invalidates dependent grants before commit and leaves relied-upon historical actions attributable.
- GOV-01 freezes a server-derived permanent-member set and stores the exact document hash. GOV-03 stores a decision over that exact hash. GOV-04 locks terms, member rows, confirmations and the organization active pointer and either commits all or none.
- NAME-01 stores an attributed statement and optional self-supplied reference only. It does not call a registry, perform search/clearance or return legal advice.
- TRE-02 is a local authorization record for a downstream single-payee boundary. A downstream payment system, provider operation, balance, split, escrow or tax record is outside this shard.
- LIFE-01 records finite dispositions and may enter closing before closed. LIFE-03 requires the active governance vote and records unresolved dispositions without blocking terminal state. LIFE-04 creates a fresh canonical party and immutable predecessor/successor row.

### Read projection and cursor obligations

ORG-02 public output is an allowlisted projection and never varies based on an unauthenticated guessed context. MEM-06, REP-04, GOV-02, NAME-02 and TRE-01 omit private fields unless the caller’s current context passes the matching RLS predicate. AUTH-01 omits revoked/expired source rows from active projection and returns a safe stale/empty state only after authority checks. LIFE-05 follows only the requested organization’s lineage and cannot be used to enumerate parties.

Collection cursors use BE00’s opaque authenticated format: route, normalized filters, deterministic sort/tie-breaker, audience, user/acting context and contract version are bound into the cursor; expiry is at most 24 hours; tamper or cross-context reuse is 400 without cursor internals. Collection limits are 1–50/default 25. Protected reads use no-store and never put terms, mandates, member lists or treasury details in Realtime hints.

Every route inherits BE00’s route registry, request deadline, no-store default for protected data, X-Request-Id, response validation and four-field ApiError. ORG-02 is the only route with an anonymous projection. Existence-sensitive unauthorized reads return 404; authenticated policy denials that do not reveal existence return 403 with only a reasonCode.

## Request/Response Contracts (Zod 4 schemas)

Zod 4 runtime schemas are strict and are the source for TypeScript, Hono validation, OpenAPI and tests. The following examples are normative shapes; optional fields remain absent rather than null unless the table says nullable. Unknown keys fail. All UUIDs are lowercase canonical UUIDs, all timestamps are RFC 3339 UTC, all date-only values are ISO dates, and all arrays are deduplicated in canonical order before hashing.

### Common wire schemas

    const Id = z.string().uuid();
    const Version = z.string().regex(/^[1-9][0-9]{0,18}$/)
      .refine((value) => BigInt(value) <= 9223372036854775807n, "version_out_of_range");
    const IdempotencyKey = z.string().min(8).max(128)
      .regex(/^[\x20-\x7E]+$/)
      .refine((value) => value.trim() === value, "idempotency_key_outer_whitespace");
    const Currency = z.string().regex(/^[A-Z]{3}$/);
    const MoneyMinor = z.number().int().nonnegative().safe();
    const Timestamp = z.iso.datetime({ offset: true });
    const StrongETag = z.string().regex(/^"[1-9][0-9]{0,18}"$/);
    const Activity = z.enum(["book","sign","spend","list","release","settle","administer","negotiate","bind"]);
    const DomainCode = z.string().regex(/^[a-z][a-z0-9_.-]{0,63}$/);
    const PartyId = z.object({ partyId: Id }).strict();
    const MutationHeaders = z.object({
      idempotencyKey: IdempotencyKey,
      ifMatch: z.string().regex(/^"[1-9][0-9]{0,18}"$/),
    }).strict();

MutationHeaders are HTTP headers, not body fields. The server rejects a body containing idempotencyKey or ifMatch. If-Match follows BE00’s exact grammar at lines 341–346: one strong quoted positive bigint, no weak tag, wildcard, list, internal whitespace or leading zero. New aggregate commands omit If-Match only when the route registry explicitly says so.

## Database Schema

### Schema and ownership boundary

Canonical relationship state lives in non-exposed schema identity_private. Browser roles have no table grants. Hono calls migration-owned security-invoker RPCs and allowlisted security-invoker views. RLS is enabled and forced on every mutable/private table. Any exceptional security-definer RPC has an empty fixed search_path, fully qualified names, PUBLIC execution revoked, named grants only, and positive/negative tests. The existing Party and PersonParty foreign keys are references to companion-owned canonical records; this spec never duplicates their identity fields.

All mutable canonical tables carry created_at, updated_at and positive bigint version unless marked append-only. Server actor/context fields are derived, never accepted from JSON. Protected columns are omitted from public projections.

`identity_private.organization_actor_grant` is the identity-owned effective-authority projection of an organization-scoped capability held by a person: one row per `(organization_id, person_id, capability_code)` with `valid_from`, an optional `valid_through` (both UTC dates), `active`, and timestamps. Identity owns the table and its schema; consumers read the row as the person's effective authority for the capability and apply their own current-term and active checks. The Shard 03 CMS capability grant RPCs `cms_grant_capability`, `cms_renew_capability_grant` and `cms_revoke_capability_grant` (BE03a CMS-03A-15 through CMS-03A-17, DEC-119) are acknowledged writers of this projection for CMS capability codes only: each upserts or ends the matching row in the same transaction as its CMS-owned aggregate, event, audit and outbox rows. The forward migration that backfills CMS grant aggregates from the owner-initialization rows reads those projection rows and writes only CMS-owned aggregate rows. They never write a non-CMS capability code, never create or alter organization, person or membership state, and no other module writes this table outside the identity-owned RPCs.

The IA typed-field registry’s generic core keys are normalized without duplicating authority: logical id maps to the physical primary key shown below; logical state maps to the row’s explicit state or temporal active/ended status; owner_id is a nullable derived owner/control reference where ownership can be ownerless and is never caller-writable. The deep-dive names remain the canonical domain fields. This mapping resolves the registry’s generic owner/state requirement against the deep-dive organization fields and keeps lifecycle separate from ownership_state.

### Retention, tombstones and deletion

- Organization, type, tenure, capacity, representation, mandate, governance, confirmation, statement and lineage history is retained as immutable evidence. Removing a surface ends/marks the row; it never hard-deletes relied-upon history.
- Rejected membership assertions retain only a protected evidence reference and safe state; public reads cannot discover the rejected assertion or evidence.
- Authority projections are disposable derived records. Revocation deletes/invalidates the active projection within the revocation transaction and queues idempotent rebuild; the source relationship and audit remain.
- Duplicate-review and attempt summaries follow the Shard 00 30-day operational retention unless a legal hold or owning policy extends it. Normalized hashes are not reversible names.
- Treasury authorization is retained as policy evidence, not as money history. Any payment provider or ledger owns its own retention and deletion contract.
- A restored database never purges lineage or source history to make downstream state look current. Recovery marks stale projections and reconciles them from canonical rows.

## Middleware & Policies

### Inherited Hono order

BE00 lines 255–269 are normative: route registry/request ID; transport/security; raw webhook branch; Supabase session authentication; acting-context resolution; strict Zod validation; capability/resource authorization; idempotency and CAS; one RPC transaction; response normalization; observability completion. This shard adds no Auth provider mechanic. User JWT metadata, URL context, body actor IDs and Queue claims cannot grant authority.

### Exact ten-step authority resolution

Every protected read and command runs these steps in order inside the same transaction that commits the mutation. A failure stops before canonical mutation, audit success, or outbox success.

1. Verify the Supabase session and active account through the Shard 00 authentication boundary; derive one human/person UUID.
2. Load the requested acting party from server-side context; reject client-provided identity, role, capability and party claims.
3. Resolve self, alias, organization membership or representation only when the relationship is active, accepted and within its date/term; this spec does not implement alias mechanics.
4. Select one current mandate source: active governance projection, explicit active grant, or the exact band default. Never union expired, revoked, pending or unreadable sources.
5. Require the requested activity in that source; for representation also require the requested domain. Membership domains are all only when the source says all.
6. For send/reply/notice actions require communicate separately, regardless of commercial activity grants.
7. Require territory, term, resource lifecycle/visibility and any domain invariant; consumer-owned purpose capability is an additional conjunct. Shard 30’s announce_waive is never generated, implied or returned by this resolver.
8. For money compare integer minor units and exact ISO currency to the source ceiling/default. No automatic conversion; null ceiling fails every monetary action.
9. Recheck resource lifecycle, policy/NDA/visibility, expected version, RLS and RPC predicates immediately before write.
10. Commit canonical mutation, authority-source snapshot, audit decision, idempotency result and outbox event atomically.

The decision record includes human, acting party, source relationship, source mandate, source version, activity, domain, term, territory, ceiling/currency, resource predicate and any explicit consumer capability reference. The consumer capability reference for announce_waive is always absent in this shard; Shard 30 records it in its own aggregate.

### Principal matrix and policy details

| Principal | Allow | Deny / disclosure |
|---|---|---|
| Anonymous | ORG-02 publication projection only | Membership, mandates, governance, treasury and private name statements |
| Self person | Accept own invitation, assert own historical tenure where policy permits, confirm governance as required member | Fabricate organization consent, add org type, grant mandate or act for another party |
| Organization member | Read permitted roster/governance and act through current accepted mandate/default | Membership presence alone grants no generic authority outside explicit band seed |
| Owner/admin | Manage types, relationships, mandates, eligible governance, name and lifecycle within current grant | Exceed grant, rewrite history, adjudicate name/legal ownership, infer Shard 30 capability |
| Representation participant | Conjoined activity/domain/territory/term/ceiling/communicate scope | Unscoped private access, ownership transfer, generic monetary action or alias disposal |
| Operator | Named capability, recent step-up, reason and bounded evidence projection | General browsing, arbitrary merge, legal adjudication or direct table edit |
| Queue/service principal | Registered event/job/projection with lease and current canonical re-read | Interactive authority, wildcard party access, provider/Queue claim as authorization |

High-risk commands (membership end, representation confirm/revoke, mandates, governance, treasury and lifecycle) require recent step-up where the route policy says high-risk, named capability and reason. ## Data Flow

### Protected mutation transaction

1. Middleware creates validated RequestContext and normalized request hash.
2. Domain RPC revalidates human, acting party, relationship, target, lifecycle, current terms and If-Match.
3. Idempotency record reserves the operation under actor, operation ID and key hash. Same key/hash waits/replays; different hash returns IDEMPOTENCY_MISMATCH.
4. RPC locks the aggregate and relevant source rows, runs the ten-step resolver, checks unique/exclusion/state constraints and writes canonical rows.
5. The same transaction writes authority snapshot, audit allowed/completed or failed evidence, any implementation record, outbox event and idempotency response.
6. Commit success returns authoritative resource/ETag; a lost response replays exact result. Commit failure creates no canonical mutation or trusted event.
7. Immediate outbox dispatch is best effort; BE00 sweeper leases undispatched rows. Queue consumers re-read current rows/version and never trust event payload as state.

### Idempotency, ETag and CAS contract

- ORG-01 uses operation ID ORG-01 and actor-bound Idempotency-Key; all other mutations use their route operation ID and require the key. Key reuse with the same normalized request, actor, acting party, target, contract version and expected version replays the original status/body/ETag. Changed body, target, context or version returns 409 IDEMPOTENCY_MISMATCH.
- BE00 canonicalization applies before hashing: strict Zod output, sorted object keys, absent optional keys omitted, NFC strings, lowercase UUIDs, RFC3339 UTC, canonical integers and no non-finite numbers. Raw JSON key order cannot create a second effect.
- Mutable organization, assignment, tenure, edge, mandate, terms, confirmation, authorization and lifecycle rows use the exact strong quoted If-Match tag. A missing or malformed tag is 400; an authorized stale tag is 409 VERSION_MISMATCH. No unapproved 428 response is introduced.
- CAS occurs after the ten-step authority recheck and inside the same RPC as state, source snapshot, audit, outbox and idempotency completion. A losing concurrent writer creates no state, event or new idempotency result.
- Dual representation confirmation locks the edge and both party confirmation columns. Governance activation locks the proposal, current permanent-member rows, confirmation rows and organization pointer. Mandate revocation locks the source and all dependent grants in deterministic ID order.
- A transaction that times out at the client is reconciled with the original key before a retry. A provider or queue ambiguity cannot be marked failed_retryable in this shard because no provider effect is owned here; canonical relationship status is re-read instead.

### Organization creation and duplicate detection

ORG-01 validates exactly one mode and registry types. The transaction creates OrganizationParty, a confirmed self membership only for self_member mode, no inferred membership for shadow/custodial or external-reference mode, initial type assignments, a duplicate-review implementation record and identity.organization.changed.v1. Type-aware duplicate detection runs before commit with a hard two-second bound when available. On timeout the organization still commits; a duplicate-review job continues from the normalized input hash. A possible match opens an explicit review/claim/merge offer; there is no silent merge and no reattribution.

### Relationships, governance and lifecycle

- Type add/removal writes one assignment at a time. Removing the last type leaves a typeless collective. Type-specific fields remain undiscoverable until the owning domain gate passes.
- Invitation acceptance locks the invitation, tenure and current governance terms. A historical assertion stores protected evidence and grants no current authority. Ending now revokes immediately; contested retroactive dates preserve current revocation and record dispute without rewriting history.
- Representation creates pending scope; each party confirmation is a separate idempotent CAS. Activation is only after both confirmations. Revoke/expiry invalidates dependent projections atomically.
- Mandate grant checks requested activities/domains/term/ceiling as subset of the grantor snapshot. Revoke recursively revokes dependent subgrants and emits context revocation for each affected person.
- Governance proposal snapshots the current permanent member set. Join/leave freezes the proposal. Activation locks proposal, exact member-set hash, every confirmation and active pointer in one RPC; rejection leaves prior/default rules authoritative.
- Name statements append competing assertions and never claim clearance. Treasury authorization checks one confirmed band member, current mandate, exact amount/currency/ceiling and one payee; it never moves money.
- Ordinary closure may reopen only from closed. Band dissolution follows active governance and is terminal. Unresolved name/funds/rights obligations get explicit disposition rows. Re-form creates a new successor party and immutable lineage; no work is deleted.

### External seam contracts and no-provider boundary

This shard owns canonical relationship and governance state. It has no external identity-provider write and accepts no provider payload, provider-selected owner, or remote legal decision. ## Error Handling

### Four-field envelope and safe details

Inherited BE00 ApiError is exactly: code string, message string, requestId UUID and details object. This shard cannot add top-level status/type/title/error fields. INVALID_REQUEST/VALIDATION_FAILED use bounded FieldViolation arrays; CONFLICT may expose authorized expected/current versions and recoveryAction; FORBIDDEN exposes reasonCode only; NOT_FOUND is empty; RATE_LIMITED matches headers; DEPENDENCY_UNAVAILABLE names only dependency class and retryability; INTERNAL_ERROR details is empty.

### Failure and partial-state matrix

| Boundary | Before commit | After commit / ambiguous | Hygiene and surface |
|---|---|---|---|
| Zod/transport | No idempotency, state, audit or outbox row | Not applicable | 400/413/415/422; sanitized security telemetry only |
| Auth/context/RLS | No mutation | Not applicable | 401 or safe 403/404; never use submitted party/role |
| Unique/CAS/state | Transaction rolls back | Same-key replay returns committed result | 409 typed conflict; no lost update or reservation |
| Duplicate detector | Creation may proceed when detector times out | Review job continues from hash | Organization remains canonical; no auto-merge or reattribution |
| Membership/representation/mandate | Invalid/pending source remains unchanged | Revocation commit invalidates projection and events atomically | Past valid facts survive; no authority from stale source |
| Governance activation | Proposal/confirmation unchanged on stale set or hash | Commit fixes active pointer and event | Rejection/prior/default remains authoritative; no partial unanimity |
| Name statement | No statement on invalid fields | Competing valid statements coexist | No platform legal conclusion; prior statements remain |
| Treasury policy boundary | No authorization record if mandate/ceiling/currency/payee fails | Authorized record is replayable only | No balance, provider, split, escrow or tax effect |
| Lifecycle/lineage | No terminal transition if version/vote/disposition invalid | Successor and lineage commit atomically | Dissolution terminal; re-form, not reopen; work retained |
| PostgreSQL/RPC disconnect | Client receives typed dependency failure; transaction outcome unknown | Reconcile idempotency record before retry | Never assert failure/success from transport alone |
| Outbox/Queue | Business commit stands | Lease/sweep retries; duplicate delivery safe | Canonical state remains authoritative; DLQ/manual review visible |
| Consumer crash | No external effect before lease/current-state check | CAS and event identity prevent regression | Retry bounded; stale terminal event is no-op |
| Realtime/cache | No canonical effect | Hint loss/staleness | Authorized refetch; no compensation from hint |
| Restore/recovery import | Protected writes fenced | Restore may precede events/projections | BE00 restoreEpoch blocks consumers/effects until identity reconciliation |

Retry is automatic only for idempotent reads and registered retryable background work. An ambiguous mutation reconciles by idempotency key, resource ETag or job/operation status before retry. No provider integration is owned here; any downstream provider effect remains outside this shard.

## Observability, Rate and Abuse Controls

Every route/consumer emits the BE00 allowlisted NDJSON fields: operation, route template or consumer, request/correlation/causation/trace IDs, actor class, acting-context class, safe entity type/version, outcome, error code, duration, dependency class and retryability. IDs are hashed/omitted unless an approved operational purpose exists. Never log terms JSON, names/evidence content, person identifiers, cookies, JWTs, payee data, raw bodies or capability graphs.

Audit records are append-only for every allowed, denied, completed and failed command, with actor/context, target, reason, source relationship/mandate/version, expected/current version where safe, correlation ID and outcome. Metrics cover request count/duration/error, RLS/RPC conflict, idempotency replay/mismatch, duplicate detector latency/timeouts, authority denial reason, membership/relationship state transitions, governance activation, outbox age, queue age/retry/DLQ, projection lag, treasury refusal and lifecycle terminal transitions. High-risk traces and diagnostic errors are 100%; ordinary success sampling follows BE00.

Rate classes are explicit in the route table. Public reads are 120/min/IP with burst 30/10s; authenticated reads 300/min/user and 600/min/party; ordinary mutations 60/min/user and 120/min/party; high-risk commands 10/min/user and 10/min/party. Treasury view is limited to 120/min/user and 240/min/party. Organization creation applies friction review above 3/24h or 10 lifetime. Limits do not create permanent count-only denial, and 429 includes Retry-After and matching RateLimit headers. Enumeration protection uses concealed 404, bounded collection pages, context-bound cursors and no public membership/mandate listing.

## Release, Migration and Recovery

Migrations use BE00 expand, backfill, switch, contract ordering. Add registry/enums/tables/indexes and dual-write/backfill before switching readers; never destructively rewrite historical memberships, statements, terms, lineage or audit. Backfills are resumable/idempotent, bounded, observable and hold-aware. Grants/RLS/RPC negative tests are promotion gates.

Supabase Free provides no PITR or production RPO/RTO guarantee, so protected authority, rights, and publication writes remain disabled. Synthetic/local recovery evidence cannot open the gate. If a separately owner-approved recovery capability is later introduced, production-verified artifact/environment provenance and restoreEpoch verification must pass before the established recovery order: database integrity, RLS/RPC negative tests, idempotency/outbox/projection consistency, relationship/terms/member-set reconciliation, public projection checks, protected writes, then async effects. Replayed events re-read current authority and retain original event identity. Missing runbook/config/registry evidence disables the dependent capability; it does not create a fallback authority.
