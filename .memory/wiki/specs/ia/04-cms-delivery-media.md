## Overview

Shard 04 converts Shard 03 publication versions into safe routes, menus, discovery metadata, governed media, public/authenticated read models, previews, caches, and degraded last-known-good delivery. PostgreSQL metadata remains authoritative, Supabase Storage remains private by default, and Cloudflare serves only immutable/versioned projections. Availability never outranks privacy, takedown, rights, or authorization revocation.

## Features

- **25.04 Navigation, Routes & Discovery Metadata** — named menu locations, bounded visibility conditions, stable slugs/permalinks/redirects, canonical/SEO/social/breadcrumb/sitemap metadata.
- **25.06 Media Library & Asset Governance** — private ingest, scanning/dedup/metadata, immutable originals/renditions, accessibility metadata, rights/consent/use restrictions, references, replacement, archive/takedown/hold.
- **25.09 Content Delivery, Preview & Cache Coherence** — render-ready read models, authenticated exact-version previews, atomic publication/invalidation, last-known-good delivery, and fail-closed recovery.

## Acceptance Criteria

- **AC-DLV-01 — Create/edit menu tree:** Given Actor holds the navigation editor capability for the assigned menu, the named location is one of the code-owned launch locations, every target resolves to an active content publication, an approved internal route or an allowlisted HTTPS external URL, and every visibility predicate comes from the bounded registry, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized editor selects named location, typed targets, labels, order, parent, and bounded visibility conditions; validate reachability, cycles, depth, and target eligibility, and (6) return Versioned draft tree; active navigation unchanged; if the flow cannot complete, Cycles, orphans or depth, item and sibling overflow reject the candidate and the active complete tree stands; `javascript:` or data-URL targets, non-HTTPS or open-redirect external hosts, preview/admin/private targets and predicates needing sensitive or stale client data are rejected before save, and a rejected predicate never weakens the target's own independent authorization.
- **AC-DLV-02 — Publish menu version:** Given Actor holds the CMS publisher capability, the candidate menu version and every named route, redirect and discovery-metadata candidate are approved by a decided delivery-candidate review (DLV-16) and complete, its tree hash matches the previewed responsive variants and audiences, and the request carries the expected currently-active manifest version for that location, locale and audience class, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Preview responsive variants/audiences, approve exact tree hash/targets, and atomically activate complete location version, and (6) return One coherent tree/version; route/cache event emitted; if the flow cannot complete, A target removed or made private after approval blocks the publish preflight or is omitted per contract without leaking existence; a mismatched expected manifest or tree hash returns a typed conflict and the prior active complete tree remains; partial-tree activation is impossible because only whole locations activate.
- **AC-DLV-03 — Create/change slug:** Given Actor holds the navigation editor capability for the target publication, the proposed path normalizes to Unicode NFC lowercase safe segments under that locale's rules, it falls outside every reserved and code-declared prefix, and the current canonical path plus its redirect history are readable so the old path can be preserved, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Normalize locale-aware path, reject reserved/colliding route, preserve canonical old-path redirect, and preview inbound impact, and (6) return Draft route candidate with its draft redirect candidate; the active manifest is unchanged until DLV-02 activates the approved candidate; if the flow cannot complete, A reserved, locale-ambiguous or already-canonical path is rejected with the exact safe conflict and never shadows a code route; a redirect cycle, self loop or chain over five hops rejects activation and preserves the last valid manifest; the normalized path reservation and redirect source commit in one transaction so no half-claimed slug survives.
- **AC-DLV-04 — Configure discovery metadata:** Given Actor holds the navigation editor capability for the target publication and locale, every authored value stays inside the bounded title, description, card, breadcrumb, canonical, noindex and structured-data fields, and the current privacy, suppression, embargo, archive and legal policy state for that publication resolves, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Author bounded title/description/card/breadcrumb/canonical/noindex/structured data; privacy/embargo/legal policy overrides editor values, and (6) return Valid draft candidate with its effective projection, or explicit blocker; no protected fact leakage; if the flow cannot complete, Editorial values that would expose suppressed, unclaimed, private or embargoed facts are overridden to noindex or sitemap exclusion with an explicit recorded blocker rather than silently accepted; unresolvable policy state fails closed to that blocker (the explicit policy-unavailable state forces noindex and sitemap exclusion) instead of publishing editor values, and no refusal reveals the protected fact it is protecting.
- **AC-DLV-05 — Ingest media:** Given Actor holds the media contributor capability for the declared purpose and owner scope, the owner is within byte and object quota, the declared purpose profile whose admission rules the upload will be measured against is named, and the 15-minute upload intent is still unexpired when the bytes arrive, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Create pending object metadata and 15-minute upload intent, upload privately, detect type/checksum/metadata, scan/quarantine, and surface possible byte duplicate, and (6) return Asset reaches `ready` only after all required checks; if the flow cannot complete, A declared/detected MIME or magic-byte mismatch, quota breach or decompression risk, or an infected scan quarantines or rejects the asset with no rendition and no public object; an unavailable scanner leaves the asset quarantined so drafts may reference it but publication stays blocked; an expired upload intent must be reissued, and a duplicate-byte suggestion exposes no other owner, reference or right.
- **AC-DLV-06 — Add rights/consent:** Given Actor may add a rights claim to that asset within its owner scope, and the claim names a claimant or source with a basis, explicit use codes, ISO-3166-1 alpha-2 territories or the sole `WORLDWIDE` value, UTC term bounds, audience and any consent or evidence reference; the initial state is `claimed` because upload and possession prove nothing, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Record claimant/source, basis, uses, territory, term, attribution, consent/evidence references, and owning-domain IDs, and (6) return Rights state is explicit; upload itself proves nothing; if the flow cannot complete, An empty use or territory set is refused rather than read as universal; a self-asserted `verified`, `restricted`, `disputed` or `revoked` state is refused because only Shard 06, 10 or 20 may write those through the inbound `RevokeDeliveryEligibility` command; a refused claim leaves existing rights rows and every derived use eligibility unchanged.
- **AC-DLV-07 — Generate rendition:** Given Source asset is `ready` with a clean inspection and recorded checksum, the requested transform profile version is a registered code-owned profile that accepts the source kind, and the target use has effective rights plus the accessibility metadata that use requires, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Select registered transform profile, validate source/right/use/accessibility metadata, create deterministic rendition job/key, and (6) return Immutable rendition becomes ready or source remains unavailable for that use; if the flow cannot complete, An arbitrary or unregistered transform, an ineligible use or missing accessibility metadata refuses the job before any output exists; a failed transform leaves the rendition `failed_retryable` or `failed_terminal` and keeps the publication or reference blocked unless an explicitly approved fallback profile applies, and the private original is never exposed as a substitute.
- **AC-DLV-08 — Replace/takedown asset:** Given Actor holds the media curator capability for a replace or archive, or the rights/safety operator capability with MFA and a reason code for a revoke, erase or hold; the complete reverse reference set for the asset is enumerable, and an erase additionally requires that no active or retained reference, legal hold, evidence duty, export/backup duty or retention rule remains, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Enumerate every reference/use, preview scope, and choose replace, revoke, archive, erase, or hold. Takedown/revocation removes delivery first, and (6) return References converge idempotently; retained evidence/audit survives; if the flow cannot complete, A replacement that changes crop, meaning or rights requires per-reference preview and approval and is refused as a global silent swap; an erase blocked by a hold, evidence or retention duty is refused with a typed reason and the bytes survive; a takedown or revocation removes delivery first and writes urgent purge intent in the same transaction, and a partial provider purge stays an open incident rather than a completed one.
- **AC-DLV-09 — Query published content:** Given An active publication projection exists for the requested route, locale and audience with its required consumer set ready; the caller's anonymous or authenticated audience class resolves before selection, and only domain bindings the caller is currently authorized to see are hydrated, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Public/authenticated API selects active publication projection by route/type/locale/audience and hydrates only authorized domain bindings, and (6) return Contract-defined resource/page with immutable publication version/ETag; if the flow cannot complete, An unknown route returns the canonical redirect where one exists and otherwise an existence-safe not-found; an unauthorized binding is omitted rather than revealed; when no eligible active projection exists the response is an explicit unavailable state with a request ID and never fabricated empty or default content, and a revoked or held publication is never served from cache.
- **AC-DLV-10 — Open preview:** Given Request carries an unexpired, unrevoked Shard 03 preview token whose bound user, acting context, capability, exact version set, audience, locale and route all still match the current caller; delivery may only narrow that scope, never broaden it, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Validate Shard 03 preview token, current user/context/capability, exact version set, audience, and revocation; bypass public cache only, and (6) return No-store/noindex preview or existence-safe denial; if the flow cannot complete, A forwarded, expired, revoked or scope-mismatched token returns an existence-safe denial that reveals no draft; the response is always `no-store` and `noindex` and bypasses the public cache only, so no preview render ever enters a public cache, sitemap or search index.
- **AC-DLV-11 — Converge publication:** Given A `cms.publication.changed.v1` event names a publication inside this delivery principal's registered projection scope, the publication and its full schema/template/block/pattern/taxonomy/locale/settings version set load, and the worker holds the lease for that exact publication and version, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Consume publication event, build route/render/menu/media/search/sitemap/cache projections under one publication version, then mark each consumer status, and (6) return Public switch occurs only when required projection set is ready; if the flow cannot complete, A required route, render, menu or media-reference projection that blocks or fails keeps the prior active pointer and records the exact consumer, expected version and error code; a stale builder can never replace a newer pointer because the switch is idempotent by publication and version; a failed purge leaves version-addressed routes correct while stale canonical URLs are tracked as degraded until verified.
- **AC-DLV-12 — Serve degraded/recover:** Given A previously active verified projection exists for the requested route and audience, the caller is still authorized for it, the projection is within the route class's maximum staleness policy, and no urgent purge, rights revocation, hold or privacy block touches it, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) On control-plane/consumer failure, serve eligible last-known-good version; compare versions after recovery and rebuild/purge, and (6) return Truthful degraded status; unsafe/revoked output never served stale; if the flow cannot complete, When no safe snapshot exists, staleness is exceeded, authorization is lost or an urgent purge has landed, the response is an explicit unavailable status with a request ID and never an empty page, an unrelated locale or a draft; takedown still reaches the independent urgent purge path while the control plane is impaired; recovery compares versions consumer by consumer and rebuilds or purges stale projections and cache keys before normal service resumes.
- **AC-DLV-13 — Apply/release delivery hold:** Given Caller authenticates as the Shard 06, 10 or 20 owning-domain command principal with step-up, and the command carries that caller's own `case_id`, an explicit resolvable subject scope of asset, reference or right, a reason code, an effective time, an expected version and an idempotency key; a release is valid only from the shard that applied the hold, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Shard 06, 10 or 20 calls this protected command with its own case reference, subject scope and effective time; this shard writes or updates `TakedownCaseLink` and applies or releases the hold. This shard records the caller's adjudication and never performs one, and (6) return Hold state and case link commit under one version; affected references re-evaluate and an urgent purge is queued on apply; if the flow cannot complete, A command with no resolvable subject is refused with a typed reason that leaks no existence rather than applied broadly; a replay returns the first outcome and creates no second hold, case link or purge; an already-held subject returns the existing hold without broadening scope; one shard's release never clears another shard's hold, and a lost command is repaired by the outbox-backed reconciliation sweep, which leaves an unconfirmable subject held rather than releasing it.
- **AC-DLV-14 — Revoke delivery eligibility:** Given Caller authenticates as the Shard 06, 10 or 20 owning-domain command principal with step-up, the named `AssetRight` subject resolves and its expected version matches, and the command carries that caller's own `case_id`, a target state of `restricted`, `disputed` or `revoked`, a reason code, an effective time and an idempotency key, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Shard 06, 10 or 20 calls this protected command to set `AssetRight.state` to `restricted`, `disputed` or `revoked` against its own case reference; this shard executes the delivery consequence only, and (6) return `AssetRight.state` commits with caller attribution; ineligible uses are removed and purge intent is written in the same transaction; if the flow cannot complete, An unresolvable right, a stale expected version or a target state outside `restricted`, `disputed` and `revoked` is refused with a typed reason and no eligibility changes; a replay returns the first outcome and writes no second right transition or purge; a partial provider purge after a successful transition remains an open incident rather than a completed one.
- **AC-DLV-15 — Submit delivery candidate for review:** Given Actor holds the navigation editor capability within the subject's own editor scope, the subject is a draft menu version, route candidate (with the redirect candidates written with it) or discovery-metadata candidate at its current version, and the code-owned review policy resolves, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Re-validate the candidate with the gates of the flow that wrote it, freeze its evidence, open one review and move the candidate `draft → review`, and (6) return One open review bound to the exact subject version; the candidate is in `review`; if the flow cannot complete, An unresolved review policy, a stale version, an existing open review, an ineligible target or an unavailable discovery policy projection refuses with a typed reason and writes nothing.
- **AC-DLV-16 — Decide delivery candidate review:** Given Caller is an independently authenticated human who is not the submitter, holds an active unexpired assignment and the review capability on that frozen review, and presents recent MFA; the review is open. A capability-scoped read of the review is available to the submitter scope and to the assigned reviewer, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Recompute the frozen evidence, append one immutable decision, and at the policy-required count (one for the ordinary review policy) move the candidate `review → approved` recording the approver and approval time; a reject decision returns the candidate to `draft`, and (6) return Decision recorded; candidate approved, or returned to draft with the review closed; if the flow cannot complete, The submitter, a repeated reviewer, an expired or revoked assignment, missing or stale MFA, or drifted evidence is refused; drift invalidates the review and returns the candidate to `draft` so that nothing activates unreviewed.
- **AC-DLV-17 — Assign delivery review capability:** Given Caller is the receipt-derived owner holding the review-assign capability with recent MFA, the review is open in the owner's organization, and the assignee is an existing eligible human other than the submitter, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Create or revoke read and decide authority on one frozen review, expiring within seven days and no later than the grantor's own authority, and (6) return Assignment recorded; no identity is created and the assignment is not delegable; if the flow cannot complete, An unknown or ineligible human, a broader scope, a delegation, an over-long expiry or a closed review is refused with a typed reason.

### Global Interaction Rules

- Navigation visibility is presentation only. Every route/resource independently authenticates and authorizes.
- Menus, routes, metadata, assets, renditions, and projections are immutable versions. Activation replaces pointers, not historical rows.
- Public delivery reads only active render-ready projection tables/objects. Preview/admin reads are structurally separate and `no-store`.
- Security/privacy/takedown/rights revocation has an independent urgent purge path and overrides last-known-good availability.
- Dispute, takedown, rights and licence state reaches this shard by inbound command only (DEC-098). Shards 06, 10 and 20 call DLV-13/DLV-14; this shard never reads their stores, never subscribes to their events, never adjudicates, and declares no dependency on them. Eligibility evaluates locally materialised `TakedownCaseLink` and `AssetRight` state alone.

## Accessibility

- Menu editor/tree and public navigation support semantic lists/landmarks, keyboard move/expand, visible focus, current-page state, skip links, and mobile disclosure without hover dependence.
- Conditional navigation never leaves keyboard/screen-reader users without the equivalent reachable route; hidden navigation is not an access-denied explanation.
- Slug/redirect/SEO forms expose normalized preview, collision/loop target, canonical URL, language, and social image alternative.
- Upload and rendition progress are announced; failures identify item/recovery; media library grid has equivalent list/table view.
- Alt/caption/transcript/focal controls include previews and instructions; decorative-empty-alt is an explicit choice, not an empty validation bypass.
- Audio/video players meet keyboard, caption, transcript, focus, motion/autoplay and contrast requirements.
- Degraded/unavailable/takedown states are truthful status content and never render an empty slot that implies no content existed.

## Edge Cases

| Case                                                                                            | Required result                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Menu tree has cycle/orphan/depth overflow                                                       | Reject candidate; active complete tree remains.                                                                                                                                                                                                                                                       |
| Visibility requires sensitive/stale client data                                                 | Reject predicate; target still independently authorizes.                                                                                                                                                                                                                                              |

| Slug collides with reserved/locale/canonical route                                              | Reject with exact safe conflict; never shadow code route.                                                                                                                                                                                                                                             |
| Reviewer decides after target, tree or discovery policy drift                                   | Evidence is recomputed at decision; a mismatch invalidates the review and returns the candidate to `draft`; nothing activates.                                                                                                                                                                        |
| Assignment expires or is revoked mid-review                                                     | The decision is refused; the owner re-assigns; activation rechecks the approving reviewers' current authority.                                                                                                                                                                                        |
| Submitter reviews own candidate, or the same reviewer decides twice                             | Refused; one approving human other than the submitter is required.                                                                                                                                                                                                                                    |
| Activation names a candidate that is not approved                                               | The whole manifest activation is refused and the prior manifest stands.                                                                                                                                                                                                                               |
| Redirect loop/hop overflow                                                                      | Reject activation; preserve old valid manifest.                                                                                                                                                                                                                                                       |
| SEO marks suppressed/unclaimed/private content indexable                                        | Privacy override forces noindex/exclusion and records blocker.                                                                                                                                                                                                                                        |
| Discovery policy cannot be resolved                                                             | Authoring, submit and activation are refused with a dependency error and store or activate nothing; delivery publishes the explicit policy-unavailable state (noindex, sitemap exclusion, optional fields redacted, blocker recorded) and never editor values.                                        |
| Upload declared image but magic bytes differ                                                    | Quarantine/reject; no rendition/public object.                                                                                                                                                                                                                                                        |
| Scanner unavailable                                                                             | Asset remains quarantined; draft may reference but publication blocks.                                                                                                                                                                                                                                |
| Scan job exhausts retries, or the scanner host is unreachable                                   | The asset stays `quarantined` or `inspecting`; no verdict is inferred; a dead-lettered job is replayed idempotently; publication stays blocked.                                                                                                                                                       |
| Scan verdict checksum differs from the asset checksum                                           | The verdict is refused and the asset stays quarantined; it never becomes `ready`.                                                                                                                                                                                                                     |
| Declared size is above the recorded plan-limit profile                                          | Typed refusal naming the profile and its limit; no asset, object or upload intent exists.                                                                                                                                                                                                             |
| Image transform exceeds its time or pixel bound                                                 | The rendition is `failed_retryable` then `failed_terminal`; the publication or reference stays blocked and the original is not exposed.                                                                                                                                                               |
| Same bytes, different rights/owner                                                              | Physical dedup optional; separate asset/right/reference records and access remain.                                                                                                                                                                                                                    |
| Required rendition fails                                                                        | Publication/reference stays blocked or uses explicitly approved fallback profile; original not exposed accidentally.                                                                                                                                                                                  |
| Rights expire after publication                                                                 | Revocation event/purge removes use immediately; source asset/evidence remains protected.                                                                                                                                                                                                              |
| Replacement changes crop/meaning/rights                                                         | Per-reference preview/approval required; no global silent swap.                                                                                                                                                                                                                                       |
| Preview URL forwarded                                                                           | Current audience/capability mismatch denies; token reveals no draft existence.                                                                                                                                                                                                                        |
| Canonical publish commits but cache purge fails                                                 | New version-addressed routes remain correct; retry purge and report degraded consumer.                                                                                                                                                                                                                |
| Control plane fails during traffic                                                              | Serve validated last-known-good within policy; no admin failure blanking public truth.                                                                                                                                                                                                                |
| Takedown arrives during degraded mode                                                           | Independent urgent purge revokes unsafe output even if control plane is impaired.                                                                                                                                                                                                                     |
| No safe snapshot exists                                                                         | Return explicit unavailable state/status and request ID; never fabricate empty/default content.                                                                                                                                                                                                       |
| Inbound delivery command is replayed                                                            | Idempotent by caller shard, case reference, subject scope and expected version; the replay returns the first result and creates no second hold, purge or state transition.                                                                                                                            |
| Inbound delivery command is lost in transit                                                     | This shard's materialised hold/right state may lag the caller's adjudication, so an outbox-backed reconciliation sweep re-asserts the caller's current case set against `TakedownCaseLink` and `AssetRight`; a subject whose command state cannot be confirmed stays held rather than being released. |
| Inbound command names a subject that does not exist or is already held                          | Refuse with a typed reason that leaks no existence; an already-held subject returns the existing hold, never a broadened scope or a second case link.                                                                                                                                                 |
| Two owning domains hold the same subject                                                        | Each hold is a separate `TakedownCaseLink`; delivery stays blocked until every hold is released by the shard that applied it, and one shard's release never clears another's.                                                                                                                         |
| Inbound delivery command carries a missing, expired, replayed or mismatched principal assertion | Refused with a typed reason; nothing is written and the subject's state is unchanged.                                                                                                                                                                                                                 |
