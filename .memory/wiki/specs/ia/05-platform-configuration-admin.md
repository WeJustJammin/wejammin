# Shard 05 — Platform configuration, admin and quality

## Initial-owner operational setup (owner-approved 2026-09-10)

An empty installation has no administrator capable of issuing the first grant.
The database operator may perform exactly one audited initial-owner setup, outside
the HTTP/API grant flow, for the owner's verified and immutable Auth/person pair.
This exception is limited to `cms.schema_registry.read`, `cms.schema_designer`,
`admin.inbox.read` and `admin.audit.read` for the new owner organization. It grants
no delegation, wildcard, case-purpose, approval, or step-up exemption. Normal
CFG-11 grantor, MFA, distinct-approval and revocation rules remain unchanged.

Setup creates the WeBeJammin alias with private person linkage and an owned
organization through existing identity operations. It refuses existing CMS/admin
authority, unavailable handle, unconfirmed/inactive identity, invalid term and
replay. A preview changes no data. Commit is atomic with a singleton receipt and
operator-provenance audit; application roles cannot execute the operation. The
requested term must end after today and within seven days. Date-granularity
organization capabilities expire at the UTC midnight at or before that end,
never after it. Initial rollout is staging only. This establishes configuration,
not hosted login, MFA, alert, performance or accessibility acceptance evidence.

### CMS schema-review assignment boundary (DEC-108, 2026-10-02)

The owner-approved Slice 09 amendment defines the separate owner-only
`cms.schema_review.assign` authority in [IA03](03-cms-content-modeling.md#schema-activation-producers-dec-108)
and [BE03a](../be/03a-content-schema-registry.md). It may assign/revoke only
read/decide on one frozen CMS schema review for an existing eligible human,
bounded by seven days and the owner's effective authority. It grants no admin,
design, publishing, wildcard or generic capability-delegation authority. The
existing owner remains the sole administrator. CFG reviews remain settings-owned.

This amendment is not permission to rerun singleton owner initialization,
create real identities/grants, broaden CFG-11, or bypass current binding/MFA.
The four-capability initial-owner operation above remains unchanged; the new
named CMS assignment authority is governed by its own approved private contract.

## Overview

Shard 05 is the governed operating surface for product variables and platform administration. It owns contract-defined settings and effective-value resolution, risk-controlled changes, release flags/experiments/kill switches, admin task/search/bulk/capability/audit/diagnostic surfaces, CMS portability, accessibility/content-quality gates, and retention/hold/erasure orchestration. It does not turn secrets, authorization, money, rights, legal floors, evidence, migrations, or transactional state machines into ordinary settings.

## Acceptance Criteria

- **AC-CFG-01 — Register setting definition:** Given Registration arrives from a code or contract release rather than an admin session; the lowercase key is new and was never previously used or retired, its value kind is one of the registry's bounded kinds, its allowed scopes are chosen explicitly from `platform`, `environment`, `party`, `site`, `route`, `feature` and `user`, and its subject falls outside the protected exclusions, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Code/contract release declares immutable key, owner, type, meaning, sensitivity, allowed scopes, resolution, default source, validation, risk, audit and deprecation, and (6) return Definition artifact/version is deployed and synchronized; admin cannot mint arbitrary keys; if the flow cannot complete, An admin-minted key, a reused or retired key, a secret, binary, code or HTML value kind, or a definition covering credentials, auth/RLS semantics, legal floors, money, rights, transactional state machines, migrations, holds or security limits is rejected before persistence with no arbitrary production key and no implicit schema; the prior deployed definition artifact stays active.
- **AC-CFG-02 — Resolve effective value:** Given Definition is active and resolvable by its immutable key, the caller supplies only request context and never schema, scope or precedence, and only the candidate scopes that definition allows are built for that context, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Load definition then eligible active value versions in its explicit precedence, validating subject/scope/time/cohort and provenance, and (6) return Typed value plus source scope/version/default and evaluation time; if the flow cannot complete, A disallowed scope or a vanished parent falls to the next explicitly defined source with the change visible in provenance, never to an ambient hierarchy; a missing required default raises a diagnostic error rather than guessing zero or empty; a consumer that cannot accept the version uses its last compatible value or contract fallback, opens a diagnostic, and never coerces an unknown type.
- **AC-CFG-03 — Propose setting change:** Given Actor holds the settings editor capability for that definition, the chosen scope is one the definition permits and the actor's grant covers, the entered value validates against the definition version's bounded schema, and the resulting effective value, consumer impact and rollback candidate are computable before the draft is offered, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized actor selects permitted scope, enters typed value, sees effective-value/consumer impact, validation and rollback candidate, and (6) return Draft change version; no effect; if the flow cannot complete, A scope broader than the actor's grant, an undefined key, a value failing the definition schema, or an attempt to lower the definition's risk class is refused before the draft is written; because a draft has no runtime effect, a refusal changes no effective value and the current active version keeps serving.
- **AC-CFG-04 — Approve/schedule/activate/rollback:** Given Candidate value and its impact manifest are frozen by hash, the definition's risk class supplies the minimum distinct approvers, MFA freshness, canary and notification policy, each approver is distinct from the proposer, and activation additionally requires the preflight to rerun successfully against the current effective context, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Freeze value/impact hash, collect risk-required distinct approvals and step-up, preflight at activation, atomically activate and emit outbox. Rollback creates a new version, and (6) return Consumers converge by version; history remains; if the flow cannot complete, Self-approval, an edit to the candidate during review, stale MFA or a missing distinct approver returns a typed refusal; any change to the candidate or effective context invalidates the approval and returns the candidate to review; a consumer that does not recognize the activated version fails safe on its prior compatible value and reports a diagnostic, and a rollback is a new forward version rather than an erasure of history.
- **AC-CFG-05 — Manage release flag:** Given Actor holds the release manager capability for that flag's environments, the flag declares a named owner, environments, cohort key, safe fallback, dependencies and a start, end and expiry, and its purpose is release availability alone, evaluated only after authentication and authorization have already decided access, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Define owner, purpose, environments, cohorts, fallback, dependencies and expiry; evaluate after auth but never as auth/business rule, and (6) return Versioned release state with automatic stale-owner/expiry task; if the flow cannot complete, A flag used as an authorization, legal or business rule is a hard denial with no override; a missing owner, fallback, dependency or expiry blocks the version; when the owner leaves or the expiry passes the safe fallback activates, a cleanup task and notification are generated and a stale-flag diagnostic opens rather than the flag silently persisting.
- **AC-CFG-06 — Run experiment:** Given Actor holds the experiment operator capability, the experiment declares a hypothesis, allocation, metrics, stop condition and end date, every eligibility dimension is drawn from the allowlisted non-protected product context, and the analytics consent contract covering those subjects is referenced, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Require hypothesis, eligible non-protected cohort dimensions, consent/analytics contract, allocation, metrics, stop condition and end date, and (6) return Deterministic assignment; experiment cannot alter safety/legal/rights/money/eligibility floors; if the flow cannot complete, Protected, special-category, private-content or inferred-vulnerability dimensions are rejected outright, as is any variant that would move a safety, legal, rights, money or eligibility floor; cohort drift freezes or stops the experiment per its declared stop rule and never silently rebalances historical assignment, and an allocation change creates a new version rather than rewriting past exposure.
- **AC-CFG-07 — Activate kill switch:** Given Actor holds the incident operator capability for that specific predeclared switch, completes step-up authentication, selects a scope the switch version already allows, states a reason and confirms the presented impact; the switch's safe fallback and signed runtime contract version are already compiled into the runtime, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Named incident-capable actor step-ups, selects predeclared switch/scope/fallback/reason, and confirms impact; independent runtime snapshot path applies, and (6) return Immediate bounded safe fallback plus immutable incident/security audit; if the flow cannot complete, An unassigned switch, an undeclared scope, a missing reason or stale step-up is refused and nothing changes; a switch can never bypass authorization or create an alternate business truth, so such a request is a hard denial; if the control plane is unavailable the last signed runtime snapshot and predeclared fallback still apply, and the incident actor, reason and version reconcile into canonical evidence when the store returns.
- **AC-CFG-08 — Work admin inbox:** Given Actor authenticates with at least one current named admin capability and the query is scoped to the task classes those capabilities cover; each task projection carries the source type, ID, version and freshness stamp needed to recheck the owning domain, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Query assigned approvals, failed jobs, schedules, expiring rights/credentials/flags, holds, diagnostics and incidents under current capabilities, and (6) return Counts/items include freshness/partial/unknown; missing card never means no work; if the flow cannot complete, A failed or lagging dependency marks that card or aggregate partial or unknown with its freshness stamp and never renders zero or an absent card, because absence must never read as no work; a task whose source domain no longer agrees is refused at completion and the projection refreshes from the owning domain rather than from the inbox.
- **AC-CFG-09 — Search/filter control plane:** Given Query names only entity types, fields, filters and sorts the registered search schema allows, the actor's current capabilities resolve before the query runs, and both per-result and aggregate count authorization apply before any response is composed, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Search allowlisted metadata/projections across content/media/navigation/settings/jobs/audit-safe refs; results enforce per-item capability, and (6) return Bounded cursor result; no body/evidence leakage through snippets/counts; if the flow cannot complete, An off-schema field, filter or sort is refused rather than silently degraded; a count that could reveal a protected case is suppressed, bucketed to the minimum-count policy, or the query is denied outright, and no snippet, facet or total may become a side channel; results are always cursor-bounded rather than truncated silently.
- **AC-CFG-10 — Preview/run bulk action:** Given Command key is in the registered bulk command registry, the actor holds the capability that same command requires individually, the dry run has frozen an exact ordered target ID and version manifest within the protected maximum batch size, and the run request carries that manifest hash plus an idempotency key, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Filter candidates, freeze exact target IDs/versions and command, dry-run eligibility/effects, approve, then process idempotent bounded job, and (6) return Per-target success/failure/retry evidence; no arbitrary database editing; if the flow cannot complete, Raw SQL, an expression or an unregistered command is refused outright; execution runs only the frozen manifest, so a target changed since the dry run fails that item alone on version mismatch and the target set can never expand; capability revoked mid-job denies new leases and stops remaining items while completed authorized items stay audited, and a cancel leaves completed effects in place for an explicit compensating command.
- **AC-CFG-11 — Grant/revoke admin capability:** Given Grantor holds an administrative capability already containing every action and resource being granted, the grant names explicit actions, resource type and ID, scope and a mandatory end time with no wildcard, and a protected or elevated grant additionally requires MFA, a stated reason, a distinct approver and recipient notification, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Capable administrator grants named scope/actions/term with least privilege; protected/elevated grant requires MFA, reason, distinct approval and notifications, and (6) return Grant becomes current or immediately revoked; sessions/actions recheck; if the flow cannot complete, A wildcard action or resource, a missing end time, a grant exceeding the grantor's own authority, or a support purpose grant carrying grant or revoke actions is refused and no grant exists; revocation takes effect immediately with no restoration except by a new grant, and every session and in-flight action rechecks the grant at commit so a revoked actor cannot continue on a cached decision.
- **AC-CFG-12 — Inspect audit/diagnostics:** Given Actor holds the named capability for the audit scope or diagnostic being read, the request resolves through a minimal projection linking content revision and change IDs to immutable audit and security event IDs without copying protected payload, and a diagnostic run names a registered definition version with its declared inputs, timeout and freshness window, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Read linked editable-history and immutable security/financial audit through minimal projections; run registered diagnostics with freshness/evidence, and (6) return Unknown/stale stays unknown; diagnostic never becomes second truth or auto high-risk repair; if the flow cannot complete, A timeout, an unavailable dependency or a stale input yields unknown or stale and never healthy, and the definition's runbook or manual check is offered instead; a diagnostic result never becomes a second source of truth and never triggers an automatic high-risk repair; an audit read outside the actor's capability is refused without revealing the protected payload it covers.
- **AC-CFG-13 — Import/export/restore:** Given Actor holds the capability for the named scope; an import uploads privately with an explicit source format, version, mapping, provenance and duplicate strategy and passes a dry run before any commit, an export names an allowlisted scope and field manifest with actor, purpose, encryption, expiry and download limit, and a restore targets an isolated non-production environment first, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorize scope, upload privately, map versions/fields/relations/media, dry-run and quarantine; export allowlisted manifest; restore into isolated target and verify, and (6) return Import commits via idempotent batches; export expires; restore proof records integrity; if the flow cannot complete, An import row asserting ownership, authority, consent, verification, money, rights or legal status is quarantined or rejected and survives only as a source-marked claim; an export whose fields fall outside the allowlist is rejected as a job so no artifact ever becomes downloadable; a restore passing counts but failing schema, hash, reference, RLS, render or accessibility verification fails and is never promoted, because backup success without restore proof is failure; interrupted imports resume from their exact cursor in idempotent batches.
- **AC-CFG-14 — Run quality/retention action:** Given A quality run names a registered code-owned checker version against an exact target version; a retention action requires the privacy/legal operator capability with MFA, a request type of `archive`, `delete`, `anonymize`, `hold`, `release_hold` or `erasure`, a verified subject and scope, and a completed cross-store manifest enumerating rows, revisions, projections, objects, caches, exports, backups, processors and third-party references, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Execute registered accessibility/content checks; preflight publish; request archive/delete/anonymize/hold/erasure; calculate cross-store manifest and conflicts, and (6) return Eligible action converges with evidence; legal/record conflicts route review and never silently erase obligations; if the flow cannot complete, A blocking structural, reference, accessibility, privacy, rights or legal finding blocks the publish and alerts the owner while the last active output remains, and warnings never invent facts or replace human review; an erasure conflicting with a legal hold or a jointly authored record preserves the required minimum, seals and minimizes access, records the exception and reviewer, and continues only the eligible processor deletes; partial completion stays open with truthful status rather than reporting success.

### Global Interaction Rules

- Anything product-operable is a typed governed setting/definition or explicit code/rule-pack invariant; scattered product literals are prohibited.
- Settings, flags, experiments and kill switches are four distinct contracts. None grants identity, authorization, consent, entitlement, legal status, money, rights, or evidence truth.
- Every administrative count, search result, task and diagnostic is capability-filtered and freshness-labelled; absence never substitutes for failure/unknown.
- Enterprise SSO, directory sync, SCIM, organization policy consoles and enterprise-wide administration remain deferred.

## Contracts

### Setting Definition and Resolution

| Contract             | Locked rule                                                                                                                                                                                                    |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Definition identity  | Lowercase immutable key/UUID owned by code/contract release; label/help may version; key never reused.                                                                                                         |

### Access Escalation

A denial returns a typed reason and preserves canonical state. Three routes exist and they are not interchangeable.

- (a) A **capability or authority denial** — missing, expired or revoked grant, insufficient scope, stale MFA — escalates to the `grantor` recorded on the actor's `AdminCapabilityGrant`, or to a capable administrator per CFG-11 where no current grantor exists. It never routes to Trust & Safety.
- (b) An **evidence or party-authority dispute about the target of a change** routes to the Shard 06 scoped case path.
- (c) **Mechanical recovery** — a stuck job, a lost artifact, an unresolvable request ID — is performed by a Support operator under a purpose grant naming that single object; a Support operator can never grant, widen or restore a capability.

Counsel, capability and privacy hard gates have no role override by any route. Per-capability routes:

- **Settings editor:** denial for an unassigned definition or out-of-scope value escalates to the grantor via CFG-11. Key creation, scope broadening, risk lowering and secret access are hard denials with no route.
- **Configuration approver:** self-approval of a protected change and editing a candidate during review are separation-of-duties hard gates with no escalation.
- **Release manager:** using a flag as an authorization, legal or business rule is a hard gate with no override. Environment or canary scope denial escalates to the grantor via CFG-11.
- **Experiment operator:** protected-trait targeting and covert access/price/eligibility discrimination are hard gates with no override. Cohort, metric or consent-scope denial escalates to the grantor.
- **Incident operator:** denial of an unassigned kill switch or break-glass escalates to the break-glass grantor and issues under the Capability grant contract with MFA, reason, bounded term, notification and evidence. Arbitrary mutation and permanent elevation are hard denials with no route.
- **Admin operator:** task, search or bulk scope denial escalates to the grantor. A request to reach a party's private data routes to the Shard 06 case path or to a Privacy/legal operator — never to a broader admin grant.
- **Portability operator:** import, export or restore scope denial escalates to the grantor via CFG-11. Wildcard export, protected-evidence or secret export, production restore and promotion are hard denials with no route.
- **Quality operator:** checker or target scope denial escalates to the grantor via CFG-11. Waiving a blocking finding or deciding a legal exception is a hard denial with no route.
- **Privacy/legal operator:** hold, erasure and third-party-rights conflicts escalate to counsel; the counsel gate has no override. A denied ordinary-content read beyond the case has no escalation route.
- **Service principal:** no human escalation route exists. A denial is a typed refusal to the caller plus an operations task against the registered consumer; a Support operator may not recover a service principal by grant.
