## Counting conventions

- Each BE operation contributes one happy-path row (two for CMS-03A-14 create and revoke, CFG-05B-06 completed and reconciling), one row per request field x constraint including the mutation or read headers, one row per distinct validation message, one row per HTTP status in its error matrix (401 UNAUTHENTICATED and 401 STEP_UP_REQUIRED are separate; 502, 503 and 504 are separate), one row per allowed and denied principal, one row per ownership, idempotency, concurrency and rollback rule and one row for its rate rule.
- A rule stated in both an error cell and a field or scoping constraint is counted once, at the field or scoping row; the matching status is counted once at the error row.
- Operation rate numbers for CMS-03A-09 to 11, 13 and 15 to 18 appear only in the contracts; BE03a states the class and examples (10/20 on 04 and 14, 30/60 on 12), so those rows count the class rule once per operation (see gaps).

- BE03b and BE03c consumed boundaries count only the integration rows and the service-only template resolver; the CMS-03B-10, CMS-03B-11, CMS-03B-01 and CMS-03C-01 items stay in Slices 10 and 12.
